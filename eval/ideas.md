- **(paused for the Sol baseline; previously lane b)** **Tell the agent about Adam's earlier applications to the same company.** Claude pass 1 completed seven audited runs and two submissions, but no prior-application question exercised the change; no verdict yet. Before resuming, fix the unsupported inference that an empty URL-matched history proves "No": tenant aliases can hide known applications. - **Conditional full-time availability is not an internship graduation date.** Cloudflare run 20261005-054712-1 submitted a return-to-school/available-upon-graduation answer instead of the supported full-time availability after December 2026. - **Deny permission prompts at launch.** Oracle run 20261005-111550-3 stopped `unsafe_permissions` because the careers page opened Chrome's "wants to: Know your location" window before the agent did anything. Launching Chrome with `--deny-permission-prompts` denies such requests silently: on that page, a fresh profile without the flag showed the prompt window and one with it showed none. The flag persists nothing in the worker profile, so it cannot leak into later runs. Denying never grants access, so the hard stop stays for sites that require camera, location, or screen access to apply. The dev lane carries it for Other sites; for `main`, it needs an experiment.
- **Scope page clicks to the webpage, not Chrome's controls.** In C3 AI 20261005-095017-3, the 112-second native Close click selected the browser tab's close button: its parent was the tab radio, not an AXWebArea. The sole tab disappeared, producing wrong-target/stale-binding refusals. Match page buttons within their web-area ancestry rather than taking the first role/label match. Native menu options need their existing separate recipe. Test this independently; do not hide an accidental tab closure with raw DevTools recovery.
- **Distinguish application-time and start-time degree requirements.** GM 20261005-095017-5 stopped before the form because Basic Qualifications said “recently completed” and within the past 12 months. The posting's 2026 start and May 2025–August 2026 graduation window are explicitly preferred; no mandatory pre-December start or application-time deadline was shown. Correctness is not established under the existing rule that an in-progress degree counts by role start. Keep the settled row intact while clarifying this case; do not assert that the employer will accept a later start. Test any wording change separately from paired-degree windows and CUA safety, retaining stops for an explicit application-time credential deadline or an unavailable degree by a fixed start.
- **Read degree alternatives before rejecting.** Grok baseline run 20261005-020930-3 rejected an ML new-grad posting as MS/PhD-only. Its official Workday description actually says “PhD or MS ... or equivalent experience required” with a December 2026–June 2027 graduation window. Adam’s B.S. falls in the window and his ML internships support the experience route. A degree with an explicit equivalent-experience alternative is not a hard degree miss; assess that route without claiming an unearned degree. The incorrect settled failure was cleared and the posting requeued for this experiment.
- **Preserve provider errors after an empty assistant turn.** Runs 20261005-013745-2 through 20261005-015354-6 contain explicit Claude five-hour rate-limit errors. Several then emit an empty assistant message, and `pi.final_message` overwrites the error with an empty string, hiding the cause in `no_result`. Keep the actual provider error when no final result follows; test the error-then-empty sequence. All 15 affected runs are excluded from experiments, not graded as model failures.
- **Uploaded attachments can leave an empty native input.** In Grok run 20261005-020930-1 (Decagon, Ashby), turns 14–24 repeatedly uploaded the resume and transcript because some input refs still said “No file chosen”. The rendered transcript widget at 367 seconds already displayed `unofficial_transcript.pdf` with Delete/Replace, and the resume’s autofill input retained its filename. Verify the actual required attachment widget, not the separate autofill input or a cleared native file-input value; re-upload only when that widget lacks the expected file. Do not mistake an autofill-only resume for the required attachment.
- **Click snapshots carry screenshots nobody looks at.** In run 20261004-221243-0 (GM, Workday), every click took a fresh `get_window_state` (56 calls, 2.4 s each, 134 s) and then the `click` itself (49 calls, 2.7 s each, 133 s): a third of the run's first 13 minutes. `get_window_state` returns a full screenshot by default, and its docs call `include_screenshot: false` "the cheap path when you're just re-indexing before an element ax action"; `query` also narrows the tree to matching rows. The prompt's click recipe passes neither. Add both to the recipe. Measured on a Finder window: the default call took 1.8 s and returned 915 KB; with `include_screenshot: false`, 1.1 s and 32 KB with every token; adding `query` cut it to 3 KB. Separately, tokens stay valid until the window's next snapshot, so several clicks on one unchanged page could share a snapshot.
- **Use the public Greenhouse form instead of an unresponsive employer wrapper.** Sol baseline run 20261005-140609-2 (Waymo) stopped `stuck` after 4.8 minutes: the wrapper's work-authorization combobox exposed no typing action and stayed closed after native click, Space, and Alt+Down. Earlier successful run 20261005-114545-5 navigated the same employer's official Greenhouse embed at 74 seconds and filled editable dropdowns there before a verified receipt. These are different requisitions, not a controlled comparison. Investigate a general route-selection rule using the posting's actual board and job ID; preserve the requested requisition, authorization, validation, and CAPTCHA handling. Do not count this as a model-speed improvement or retry a submitted job.
